# Applets for Quickshell

Tiny desktop apps for [Quickshell](https://quickshell.org). Put a folder with
a manifest and one script (or one QML file) in `~/.config/applets/`, and it
becomes a bar item, popup, window or desktop widget in your shell's theme, with
a keybinding, persistent storage and live reload. Claude or Codex can write
applets from a description.

A personal project, not affiliated with the Quickshell project. The
command-line tool is `qsa`.

```toml
# ~/.config/applets/tz/applet.toml
name = "tz"
title = "Time zones"
entry = "main.py"
interval = 30
bar = true
icon = "◷"
key = "SUPER + CTRL + T"
```

```python
#!/usr/bin/env python3
# ~/.config/applets/tz/main.py: print one JSON object; the shell renders it.
import json
from datetime import datetime
from zoneinfo import ZoneInfo

zones = ["UTC", "America/New_York", "Asia/Tokyo"]
print(json.dumps({"text": f"{datetime.now():%H:%M}", "items": [
    {"text": f"{datetime.now(ZoneInfo(z)):%H:%M}  {z}", "copy": z} for z in zones
]}))
```

The bar shows "◷ 14:05"; clicking it opens the list below the chip, and
clicking a row copies it.

## How it works

- **Script applets** are executables in any language that print JSON. Items
  can run actions, copy text or open URLs. Applets can take text input, refresh
  on an interval, or stream updates line by line. The output also works as a
  Waybar custom module.
- **QML applets** are full Quickshell QML. They get an `applet` object (config,
  store, notify, run…) and themed components from `import qs.Applets`. A QML
  file can also be a custom bar item, such as a media player.
- **Embedded in your shell**: `AppletsHost` runs inside your own Quickshell
  config, and `AppletBar` shows bar applets wherever you place it. No extra
  process to start.
- **Surfaces**: a `popup` (centered, or attached to its bar chip), a `floating`
  window, or a `desktop` widget under (or above) your windows.
- **Theme**: pass your theme object (`theme: Theme`) and applets follow it,
  including live theme switches.
- **Live reload**: saving any file in an applet folder reloads that applet.
  QML errors show inside the applet instead of breaking the shell.

[SPEC.md](SPEC.md) is the full format: manifest keys, script protocol, QML API,
bar, theme tokens, embedding and IPC.

## Requirements

- [Quickshell](https://quickshell.org) 0.3 or later and Python 3.11 or later.
- A Wayland compositor with layer-shell (Hyprland, Sway, niri, river…).
  Hyprland adds focused-output detection for popups.
- Optional: `notify-send` for notifications, `xdg-open` for `open` items, and
  a signed-in `claude` or `codex` CLI for AI generation.

## Install

```sh
git clone https://github.com/roke75/applets-for-quickshell.git
ln -s "$PWD/applets-for-quickshell/bin/qsa" ~/.local/bin/qsa
```

Keep the clone where it is: `qsa` and the Quickshell module are used from it.
Below, `<repo>` stands for its folder.

### Embed in your Quickshell config (recommended)

```sh
qsa setup              # links the module as ~/.config/quickshell/Applets
```

Then, in your `shell.qml`:

```qml
import qs.Applets

ShellRoot {
    AppletsHost {
        id: applets
        theme: Theme          // your theme singleton; optional
    }

    // ...inside each bar, where applets should appear:
    AppletBar { host: applets }
}
```

Quickshell reloads, and applets appear as soon as you create them. To show
some applets elsewhere in the bar, give each `AppletBar` a list:
`AppletBar { host: applets; names: ["media"] }`.

`theme` reads properties named `background`, `surface`, `surfaceAlt`,
`border`, `foreground`, `foregroundDim`, `muted`, `accent`, `warning`, `error`,
`success`, `opacity`, `rounding`, `borderSize`, `fontFamily` and `fontSize`.
Missing ones use defaults. If your theme uses other names, map them:

```qml
theme: ({ accent: Colors.blue, surface: Colors.base, foreground: Colors.text })
```

### Or run it standalone

Without a Quickshell config of your own, start the standalone runtime, for
example from your compositor's autostart. It shows popups, windows and desktop
widgets, but has no bar; style it with `~/.config/applets/theme.json`
(SPEC.md "Theme tokens").

```sh
qsa daemon -d
```

## Create an applet

```sh
qsa new weather --bar  # a script applet with a bar chip
qsa toggle weather     # open it
```

`qsa new` creates `~/.config/applets/weather/` with `applet.toml` and a
starter `main.sh`. Edit `main.sh` to print your own JSON; the bar and popup
update on the next refresh. `qsa run weather` prints the output or the
error, without the shell.

Variants: `--qml` for a QML applet, `--bar-qml` for a bar-only QML item, and
`--surface floating|desktop` for other window types.

For a keybinding, add `key = "SUPER + CTRL + W"` to the manifest and paste the
output of `qsa binds` (Hyprland Lua) or `qsa binds --sway` into your
compositor configuration.

### Generate with AI

Describe an applet and let your installed Claude Code or Codex CLI write it:

```sh
qsa new weather --bar --ai "current temperature in the bar for a city set in [config], 3-day forecast in the popup"
qsa edit weather --ai "also show wind speed"
```

The model gets `SPEC.md` and a few examples, and returns files as JSON. It has
no tools, so it cannot run commands or touch other files. The CLI writes the
files to a temporary folder and checks them without running anything: the
manifest, `bash -n` for shell scripts, Python compilation, QML imports. If a
check fails, the problems go back to the model, up to two times. You then see
the files (or a diff, for `edit`) and choose to install, test run (scripts
only, with a throwaway data folder), or discard. Nothing generated runs or
reaches `~/.config/applets` before you choose.

`--with claude|codex` picks the CLI (default: Claude if installed, else Codex).
The CLI must be signed in; no API keys are stored. `--yes` skips the review,
for scripted use.

The CLIs run isolated from your personal setup: no MCP servers, hooks,
plugins or project instructions. The model is chosen in this order:

1. `--model <name>`, for example `--model sonnet` or `--model gpt-5.6-sol`.
2. `QSA_CLAUDE_MODEL` or `QSA_CODEX_MODEL`, for a permanent choice per CLI.
3. The model in the CLI's own config: `model` in `~/.claude/settings.json`,
   or `model` (and `model_reasoning_effort`, including the active profile's)
   in `~/.codex/config.toml`.
4. The CLI's default model.

The progress line shows which one is used, for example
`Asking Codex (gpt-5.6-sol, from your CLI config)…`.

## Commands

| Command | Does |
|---|---|
| `qsa new <name> [--qml] [--surface S] [--bar \| --bar-qml]` | Create an applet from a template. |
| `qsa new <name> --ai "…"`, `qsa edit <name> --ai "…"` | Write or change an applet with Claude or Codex, then review it. Also `--with`, `--model`, `-y`. |
| `qsa install <folder\|git-url\|gh:user/repo> [-y]` | Copy an applet in, after showing its files. |
| `qsa remove <name> [--keep-data] [-y]` | Delete an applet and its data folder, after confirming. |
| `qsa list [--json]`, `qsa check [name]` | Show applets and validate manifests. |
| `qsa run <name> [--action ID \| --input TEXT]` | Run a script applet once, without the shell, and print its output. |
| `qsa setup [config]` | Embed applets in a Quickshell config (default `~/.config/quickshell`). |
| `qsa daemon [-d] [--replace]` | Start the standalone runtime. |
| `qsa toggle\|show\|hide <name>` | Show or hide an applet's window. |
| `qsa send <name> --action ID \| --input TEXT` | Trigger an action or submit input in a running applet. |
| `qsa binds [--sway]`, `qsa path` | Print keybindings, or the applets folder. |

`APPLETS_HOME` overrides the applets folder (default `~/.config/applets`).
`toggle`, `show`, `hide` and `send` talk to the Quickshell instance named by
`APPLETS_SHELL` (a config path); by default, a running standalone runtime, else
your default Quickshell config.

## Waybar

Script applets also work as Waybar modules. `on-click` needs a running shell
that hosts applets (embedded or standalone):

```json
"custom/tz": {
    "exec": "qsa run tz",
    "return-type": "json",
    "interval": 30,
    "on-click": "qsa toggle tz"
}
```

## Uninstall

Remove a single applet with `qsa remove <name>`. To remove everything, in this
order:

1. **Stop hosting applets.** If embedded, delete `import qs.Applets`, the
   `AppletsHost` and every `AppletBar` from your `shell.qml`; Quickshell
   reloads without them. If standalone, run
   `qs kill -p <repo>/runtime` and remove
   `qsa daemon` from your autostart. Remove `qsa` keybindings from your
   compositor configuration.
2. **Remove the links.** Do this after step 1, or your shell fails to load
   the missing module:

   ```sh
   rm ~/.config/quickshell/Applets ~/.local/bin/qsa
   ```

3. **Optionally delete your applets and their data:**

   ```sh
   rm -r ~/.config/applets ~/.local/share/applets
   ```

4. **Delete the repository:** `rm -r <repo>`.

## Security

Applets run as your user, without a sandbox. Only install applets you have
read, and review generated ones before accepting them.
